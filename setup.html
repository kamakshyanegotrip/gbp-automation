Open console →

Four steps, about five minutes

The console holds no data of its own. It reads live figures from your n8n webhook, authenticated with a token you create here. Nothing on this page is sent anywhere except to your own n8n instance.

Generate a token

Run this in PowerShell. It builds a 40-character random string on your machine, so the token never travels through a chat window or an email.

-join ((48..57) + (65..90) + (97..122) | Get-Random -Count 40 | % {[char]$_})

Keep the output to hand — you will paste it twice, in step 2 and step 4.

Create the credential in n8n

In n8n: Credentials → Add credential → Header Auth. Fill in exactly two fields and rename the credential itself.

Credential nameGBP Console Token
NameAuthorization
ValueBearer <your token>
The two things people get wrong here. The field labelled Name is the HTTP header name, not a label for the credential — it must be exactly Authorization. And the word Bearer, followed by one space, belongs at the start of the Value, because that is what the console sends.

Attach it, then activate

Open the GBP Console API workflow. Select the Console GET node, set its Authentication credential to GBP Console Token. Do the same on Console POST. Save, then switch the workflow Active.

Order matters. Attach the credential to both nodes before activating. An active webhook with no authentication is an unauthenticated read of the entire database, open to anyone who finds the URL.

Test and connect

Paste the webhook URL and the token. This page will call the API, tell you precisely what came back, and hand the settings to the console.

The URL and token are stored in this browser only, and are readable by anyone with access to this browser profile. Use a token scoped to the console, and rotate it if the machine is shared.
