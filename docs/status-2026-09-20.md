### Safety added before going live

- **Truncated reviews are always held.** Notification emails cut long text short;
  a draft written from half a review must never be auto-sent. This is a hold
  reason in `Parse Draft` and an amber warning on the digest card.
- **Direct review links.** Built from `discovered_account_id` +
  `google_review_id` + `discovered_location_fid`, so approving and posting by
  hand is click-and-paste. Only email-sourced rows get a link — API rows store a
  full resource name that these URLs cannot use.
- **Placeholder cleanup.** A permanent step after the upsert nulls Google's
  literal "This user only left a rating", clears any draft written from it, and
  resets `reply_status`. Repaired 2 rows.

### Two bugs the test runs caught

- The digest classified items from `Collect Results`, but that merge carries
  whatever the last node emitted — `Save Draft` returns only RETURNING ids, so
  `can_auto_send` was undefined and every count read **zero while ten drafts
  existed**. It now reads `Parse Draft` and `Record Send Result` directly.
- The upsert cannot repair a bad comment, because it never overwrites a non-null
  comment with null — hence the separate cleanup step rather than a parser fix
  alone.

### How to use it

Digests arrive every 4 hours listing held drafts. For each: read the review on
Google (essential for truncated ones), then either paste the draft reply in by
hand, or edit `ai_suggested_reply` in `gbp_reviews` and set `reply_status` to
`pending`. Automatic publishing still needs the API or a vendor like Windsor.

### Two defects the first backfill caught

- Google writes the literal sentence **"This user only left a rating"** when a
  reviewer leaves stars with no text. Stored as a comment, Claude would have
  drafted a reply to the placeholder. Now nulled — which also correctly keeps
  those rows out of the reply queue, since it requires `comment IS NOT NULL`.
- The report undercounted written rows (said 1, wrote 24): the transaction-
  batched upsert returns a single item, so the count now comes from the row set
  actually sent.

### To extend this to a client's profile

1. The client adds your Google account as a **Manager** on their Business Profile.
2. That account enables **Customer activity** notifications (not automatic).
3. Add a `gbp_locations` row whose `business_name` matches the profile name

No API access, no allowlist. For the agency model, use one dedicated mailbox for
all clients rather than a personal inbox.

## Architecture decision — multi-tenant

Assign Over is the **software publisher**; Negotrip is a **client**. The Google
Cloud project, the OAuth client and the API allowlist all belong to Assign Over,
and every client connects their own profile through the same consent screen.
This is explicitly permitted by the GBP API policies for third-party/agency use,
with three constraints that shape the build:

- A client must **not** have their own API project; access flows through ours.
- A client must sign in **manually** — no programmatic access to their account.
- Google content may be cached for **no more than 30 calendar days**.

The third one is now enforced in code (migration 008, below). The first two are
process, and belong in the onboarding checklist that still needs writing.

## Compliance work done (2026-09-05)

### Migration 008 — 30-day retention, enforced

The privacy policy and the GBP API policies both say Google content is cached
for no more than 30 days. Nothing enforced it; review text, reviewer names,
photo URLs, service copy, metrics and the full raw API snapshots were being kept
forever. `gbp_purge_expired_google_content(retention_days, execution_id)` now
**redacts rather than deletes**: it strips the Google-sourced fields out of rows
that have gone 30 days without a refresh, but keeps the numbers we derived
ourselves — star rating, reply status, response latency, photo counts — so the
health-score trend survives. Every sweep is logged to `gbp_retention_runs`.

An actively synced profile is never redacted, because the cutoff is on
`last_synced_at`.

### Quota alert (2026-09-08)

`Quota Watch` used to make the accounts request and leave the answer buried in
the execution log — useless unless someone opened n8n daily. It now feeds an IF
on `statusCode == 200` and a Gmail node, so the moment Google grants the
allowlist an email arrives carrying the **raw accounts payload** — which is
exactly the value needed to replace `accounts/PENDING`.

Verified on execution 12512: purge returned all zeros (nothing is 30 days old
yet), Quota Watch returned 429 with `quota_limit_value: "0"`, the IF routed to
the false branch, and no mail was sent. The workflow is now active on the 03:00
schedule.

## Operating notes

- **Everything runs in suggest-only mode.** With both `auto_*` flags false,
  replies and posts are drafted and held. The system is useful from day one
  without publishing anything.
- **Approving a held review reply:** set `ai_suggested_reply` to your wording
  and `reply_status` to `pending`. The next run publishes that exact text
  verbatim — it does not re-draft it.
- **Approving a held post:** set `summary` and `status = 'scheduled'` with a
  `scheduled_for` time.
- **Why a draft was held** is now in `hold_reasons` on both `gbp_reviews` and
  `gbp_posts`.
- **Health score weights:** Business Info 25%, Photos 20%, Reviews 20%,
  Profile 15%, Content 10%, Services 10%.

## n8n gotchas learned the hard way

- **Code node return shape depends on mode.** *Run Once for All Items* returns
  an array; *Run Once for Each Item* returns a single `{json: …}` object.
  Getting it wrong gives "A 'json' property isn't an object".
- **A node that outputs zero items halts the chain.** Any query that can
  legitimately return no rows needs **Always Output Data**.
- **A Postgres node runs once per input item.** If its query doesn't depend on
  the item, set **Execute Once** or it multiplies everything downstream.
- **`URL`, and probably other Node globals, are not available in the Code
  sandbox.** Parse with regex, and never let a `catch` swallow the failure of a
  security check.
- **`RETURNING` only sees the row you inserted.** To carry other columns
  forward, wrap the INSERT in a CTE and join.
- **Import from File does not auto-save.** The workflow must be saved
  explicitly afterwards or the import is silently discarded.
- **n8n expressions need `={{ $json.field }}`** — the `=` prefix *and* the
  braces. `=json.field` silently produces literal text.
- **Reviews, local posts and photos are Google My Business v4 only**, which is
  what the allowlist gates. Business info, attributes and performance are v1 and
  work as soon as quota opens.

## Google-side facts worth not re-learning

- `business.manage` is a **sensitive** scope, not restricted. Verification means
  a brand check, domain ownership in Search Console, a privacy policy, a scope
  justification and an unlisted YouTube demo — **no CASA security assessment**,
  and roughly 3–5 business days.
- The API allowlist is granted **per Google Cloud project**, not per profile.
  `quota_limit_value: 0` means still pending; 300 means approved.
- While publishing status is *Testing*, refresh tokens expire every **7 days**
  and everything stops silently. That is why In production mattered.
